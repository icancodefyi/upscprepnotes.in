# Topper Entity Page Architecture

## Goal
Each topper page is an entity: one person with typed, structured claims.

## Elements
- Verified identity (name, rank, year).
- Paper-wise marks table (official-framed).
- Strategy / methodology write-up.
- Answer copy download (verified only) + related-copy fallback.
- Internal links: same-year toppers, same-optional, related strategy.
- Schema: Person + FAQ; about/wikidata linking; speakable.

## Why
Entity-bound, factual pages are what search engines and LLMs cite. This is the
core of the 'verified topper data' positioning.
